# 07: The real labeller

**What to build:** The `label` node backed by an LLM, provider-agnostic through LangChain. `init_chat_model` with provider and model from `LabellerConfig` (provider, model, effort, optional temperature and any other sampling knob; read from the environment; temperature sent only when set because Opus 5 rejects it; default `claude-opus-5` at effort `medium`); `with_structured_output(method="json_schema")` so native structured output coexists with adaptive thinking, never a forced tool call; Anthropic-specific options isolated in one provider-configuration function. The schema is ticket 03's labelling-result type: reference tree, mandatory quote, closed rule enum, strict-compatible. The prompt is a markdown file inside the label package carrying the rules: quote verbatim and contiguously; one reference per leaf; dates as printed, one reference per range block; referees under `RM_REFEREE`; the source's own headings under `RM_HEADING`; sub-headings inside Additional Information are content; skills split at the model's judgement with parentheticals kept; anything that fits nowhere is left unreferenced, never forced into a field; images are not mentioned because the LLM never sees them. `PROMPT_VERSION` and `SCHEMA_VERSION` are hand-bumped strings and a content hash of prompt text plus JSON schema sits beside them; both appear in every `Run`. A malformed or schema-invalid answer is returned as a labelling failure value, never raised; retries are Phase 2. Tokens and cost are recorded on the `Run` from the provider's usage metadata and the price table. One spike test reaches the real model and is skipped without an API key; the spec states that **the eval is the labeller's test**. ADR-0009 is written here: LangChain with native structured output, quote mandatory, `RM_PHOTO` never the LLM's (if code can do it deterministically, the LLM doesn't get a vote), the closed rule enumeration, the strict-compatible schema, what it costs and what bounds it, and why no endpoint will ever expose the transform log (half a review queue).
