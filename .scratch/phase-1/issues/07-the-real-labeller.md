# 07: The real labeller

**What to build:** The `label` node backed by an LLM, provider-agnostic through LangChain. `init_chat_model` with provider and model from `LabellerConfig` (provider, model, effort, optional temperature and any other sampling knob; read from the environment; temperature sent only when set because Opus 5 rejects it; default `claude-opus-5` at effort `medium`); `with_structured_output(method="json_schema")` so native structured output coexists with adaptive thinking, never a forced tool call; Anthropic-specific options isolated in one provider-configuration function. The schema is ticket 03's labelling-result type: reference tree, mandatory quote, closed rule enum, strict-compatible. The prompt is a markdown file inside the label package carrying the rules: quote verbatim and contiguously; one reference per leaf; dates as printed, one reference per range block; referees under `RM_REFEREE`; the source's own headings under `RM_HEADING`; sub-headings inside Additional Information are content; skills split at the model's judgement with parentheticals kept; anything that fits nowhere is left unreferenced, never forced into a field; images are not mentioned because the LLM never sees them. `PROMPT_VERSION` and `SCHEMA_VERSION` are hand-bumped strings and a content hash of prompt text plus JSON schema sits beside them; both appear in every `Run`. A malformed or schema-invalid answer is returned as a labelling failure value, never raised; retries are Phase 2. Tokens and cost are recorded on the `Run` from the provider's usage metadata and the price table. One spike test reaches the real model and is skipped without an API key; the spec states that **the eval is the labeller's test**. ADR-0009 is written here: LangChain with native structured output, quote mandatory, `RM_PHOTO` never the LLM's (if code can do it deterministically, the LLM doesn't get a vote), the closed rule enumeration, the strict-compatible schema, what it costs and what bounds it, and why no endpoint will ever expose the transform log (half a review queue).

**Decisions beyond the ticket text.**

- **No `Run` type exists yet.** Ticket 06 (pipeline function, blocked by 05) owns `Run` and hasn't landed on this release branch; ticket 07 is blocked only by 03, and the task brief explicitly said not to depend on 04 (also unmerged) by extension the same applies to 06. So this ticket introduces `LabelRun` (config, `prompt_version`, `schema_version`, `content_hash`, `input_tokens`, `output_tokens`, `cost_usd`, `label_failed`, `failure_reason`) as the labeller's own record, recorded on `RealLabeller.last_run` after each call. **For the maintainer:** when ticket 06 builds `Run`, it should fold a `LabelRun` in (or `Run` could simply hold one) rather than duplicating these fields; the pipeline's generic `labeller: Callable[[blocks], LabellingResult]` seam from the spec is unchanged, since `RealLabeller.__call__` returns only the `LabellingResult` and the run metadata is a side-effect read afterwards, the same shape an oracle labeller (which has no tokens or cost) can satisfy for free.
- **Provider dispatch.** `build_chat_model` raises `ValueError` for any `config.provider` other than `"anthropic"`, since `anthropic_kwargs` is the only provider-configuration function that exists today; a second provider is a second sibling function and a dispatch branch, not a rewrite, per the ADR.
- **Adaptive thinking.** Not requested via an explicit `thinking=` kwarg; `langchain-anthropic`'s `ChatAnthropic` turns on adaptive summarized thinking automatically once `reasoning_effort` is set (confirmed by reading `chat_models.py`), which matches "effort set" from the ticket without hand-building the thinking payload ourselves.
- **Canned-response testing.** LangChain's built-in fake chat models (`GenericFakeChatModel`, `FakeListChatModel`) do not implement `bind_tools`/`with_structured_output`, so `method="json_schema"` structured output cannot be exercised through them (confirmed by reading `langchain_core`'s base `with_structured_output`, which always forces a tool call). The canned-response tests instead pass a `langchain_core.runnables.RunnableLambda` as the `structured_model` argument to `label_blocks`, returning the same `{"raw": AIMessage, "parsed": ..., "parsing_error": ...}` shape `ChatAnthropic(...).with_structured_output(Labelling, include_raw=True, method="json_schema")` produces (verified by reading `langchain_anthropic`'s implementation). This is a LangChain `Runnable` standing in for the bound chat model, not a `BaseChatModel` subclass; it tests the same seam (`label_blocks`) the real path uses, so nothing about the parsing/failure logic is duplicated or untested.
- **Failure handling is broader than "malformed or schema-invalid".** `label_blocks` wraps the whole `structured_model.invoke(...)` call in `try/except Exception`, so a network error, an auth failure or a rate limit also becomes a `LabellingFailure` rather than raising, consistent with ADR-0008's "a bad day for the LLM is a document under the banner, never an error page" and with retries being out of scope for Phase 1.
- **Price table.** Checked live against `claude.com/pricing` on 2026-09-23 (today, per the session's date): Opus 5 (legacy) $5/$25 per million input/output tokens, Opus 5.5 $4/$20, Sonnet 5 $2/$10. All three are in the table; an unknown model costs $0 rather than raising.
- **Env var naming.** No existing `CVR_*` convention existed in the repo; `CVR_LABEL_*` was chosen to match the package name. `CVR_LABEL_EXTRA` is a JSON blob for "any other sampling knob" rather than one variable per knob, since the set of knobs is provider-specific and open-ended.
- **Message shape sent to the model.** System message is the prompt text verbatim; human message is `json.dumps([{"block_id": ..., "text": ...}, ...])` over the parsed blocks. Not specified by the ticket; this is the simplest encoding that gives the model both id and text per block.

**Not run live.** The spike test (`tests/label/test_spike.py`) needs `ANTHROPIC_API_KEY`, which this environment does not have; it was confirmed to skip cleanly (`1 skipped`) and was not exercised against the real API. **Versions for the PR description, once it is run:** `PROMPT_VERSION = "1.0.0"`, `SCHEMA_VERSION = "1.0.0"`, default model `claude-opus-5` at effort `medium`, `langchain==1.4.2`, `langchain-anthropic==1.7.4`.
