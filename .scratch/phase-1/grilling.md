## Settled (Rounds 1 and 2, with the maintainer's amendments folded in)

- **Q1 Labelling schema**: reference-shaped `CVContent` tree (option b), depth ≤ 3, every leaf a `{block_id, quote}` reference.
- **Q2 LLM surface**: LangChain (`init_chat_model` + `with_structured_output`), provider and model from env. Stated goal: learn LangChain in a provable way. Anthropic-specific bits (adaptive thinking, effort) isolated in one provider-config function.
- **Q3 Model config**: model, effort, temperature and any other sampling knob are one `LabellerConfig` read from env and printed into every eval report. Temperature optional and only sent when set (Opus 5 rejects it). Default `claude-opus-5`, effort `medium`, tune from the baseline; a change counts as a model change for the eval-run rule.
- **Q4 Verifier matching**: match on `canonicalise()`, slice raw. The canonical→raw offset map is emitted *during* canonicalisation, never reconstructed after. Known-answer unit tests on `canonicalise` and the offset map directly. No case-folding.
- **Q8 Invisible characters**: strip at parse, log per block under `NORM_INVISIBLE`; pre-strip text discarded. Visible confusables untouched.
- **Q10 Parser**: images recorded by content hash; `Removal(rule, subject: Span | Image)`, `Image(part, sha256, size)`; block ids are real addresses with gaps (Q21); "stable" = for a fixed input file; text-box reading order = anchor order, an approximation, say so in the ADR.
- **Q11 API**: `POST /reformat` returns the `.docx` body, `X-Run-Id` on every response including 4xx/5xx, `Content-Disposition` with a derived filename; `GET /health` never touches the LLM. Post-deploy smoke step verifies the header survives Container Apps ingress.
- **Q12 Eval cost**: live LLM calls in CI; gitignored local response cache keyed `(model, prompt_version, schema_version, source sha)`; `concurrency: cancel-in-progress`; the report prints tokens and cost per run.
- **Q13 Deployment prerequisites**: personal Azure subscription; Actions enabled; GHCR now, possibly ACR before interview. Provisioning is a one-off via the `wizard` skill; the ADR records that it is manual and that Bicep/Terraform is what changes at scale (§12 item 9), ACR + managed-identity pull is the Phase 2 upgrade (§12 item 7).
- **Q14 Tickets**: one `.scratch/phase-1/spec.md`, one numbered issue sequence, pipeline first (Docker/deploy have nothing to gate against until the eval runner and baseline exist). README-as-ADR ticket early.
- **Q15 Reference shape**: `quote` is **mandatory** on every reference; a reference with no quote skips verification, which defeats the point. Cost stays ~$7/run on Opus 5; the cache and cancel-in-progress bound it. Schema-invalid tree → request-level failure → every block is residue, job completes under the banner, run logged `label_failed`. Schema-valid but wrong reference → per-leaf rejection, the entry survives with a hole. Coverage never walks the tree: the verifier walk emits a flat `(path, Span)` claim list.
- **Q16 Claim ledger**: one ledger per block of `(start, end, claimant)`. Order: LLM-labelled removals in schema order → regex backstop → content in tree-walk order (name, profile, skills, education, experience, certifications, additional; list order within). Same-string occurrences go to claimants in that order, first unclaimed occurrence. Content overlapping a removal is clipped; content overlapping content is a conflict (later claimant rejected, range stays unclaimed, so the loser surfaces in the appendix rather than vanishing). Coverage is computed last over the finished ledger, **and the node sequence verify-removals → backstop → verify-content → coverage is asserted by a unit test, not left as intention** (that ordering is what retires the Q7 worry).
- **Q17 Multi-span units**: a rendered unit may be an ordered list of Spans from one block, ascending, non-overlapping, joined by a single space (the space is template text). Only ledger clipping produces one; the LLM's reference is always one quote. Transform log records `(rendered text, [slices])`; `provenance_violations` gains a `split_map` beside `date_map`. Corruption table gains "join two slices out of source order" (fails provenance only).
- **Glossary**: *residue* = anything unclaimed, always logged; *unplaced text* = residue that is not purely separators; the joining space is template text. Written into `CONTEXT.md` (Claim, Multi-span unit, Residue, Separator, Backstop added; Template text, Removal, Unplaced text amended).
- **Q18 Separators**: `SEPARATORS` in `cvr.text` beside the confusable table: whitespace, `, ; : | / \ ( ) [ ] .`, dashes `- – —`, glyphs `• · ◦ ▪ ‣ ○ ■` **plus the common Symbol-font PUA bullets `U+F0B7 U+F0A7 U+F0D8 U+F0FC U+F076`** (defensive; the golden set never emits them, real Word documents can), quotes `' " ‘ ’ “ ”`. `&` excluded. `:` included. `C#` and `.NET` added to c07's skills as an early fixture ticket, **and pinned by a `tokenise` unit test** so the behaviour does not depend on a regeneration.
- **Q19 RM_HEADING backstop**: vocabulary only (style-matrix headings + common synonyms, case-folded, trailing colon stripped), applied only to blocks the LLM has not placed. The reasoning goes in the ADR verbatim: a false removal is silent, a false appendix entry is loud.
- **Q20 Stated limitation**: a composite line assembled in the wrong order is caught by the renderer round-trip test, not by the eval gate. The ADR says: the eval gate proves the labels; the renderer is proved by its own tests.
- **Q21 Block id grammar**: `body:12`; `table:12:r1:c0:3`; `header:0:default:2` with the header type slot `default | first | even` (footers likewise); `textbox:12:0:3`.
- **Q22 Registry**: public GHCR *package* at first deploy, no registry secret; ACR + managed identity in Phase 2. Repo goes public at the end of Phase 1, once the README-as-ADR is in place. ADR caveat: a public image is pullable by anyone, so `.dockerignore` covers `.env`, `.cache/`, `fixtures/`, `tests/` and the build is checked for baked-in secrets.
- **Q23 CI shape**: one `ci.yml`, `check` → `eval` → `deploy`. `eval` runs on `pull_request` and `push` to `main`, uploads `report.json` + markdown as artifacts **and writes the markdown into the job summary and a PR comment** so the numbers are on the PR page. `concurrency` with cancel-in-progress on the whole workflow. `deploy` on `push` to `main` only, `id-token: write`.

## Settled (Round 3)

- **Q24 Prompt**: markdown file inside `cvr.label`, loaded at import. `PROMPT_VERSION` and `SCHEMA_VERSION` hand-bumped; the cache key also hashes prompt text and JSON schema. **The report prints both the label and the hash**, so a bumped label with no text change (or the reverse) shows in a report diff. Prompt rules: quotes verbatim and contiguous; one reference per leaf; dates as printed; referees under `RM_REFEREE`; source headings under `RM_HEADING`; sub-headings inside Additional Information are content; skills split at the LLM's judgement, parentheticals kept; anything that fits nowhere is left unreferenced.
- **Q25 Structured output**: `with_structured_output(method="json_schema")`. Pin `langchain-anthropic>=1.7,<2` (documents the method; checked). The first label ticket is a spike that proves `json_schema` + adaptive thinking + `effort` work together on Opus 5 and records the versions. **The schema is written strict-compatible from day one** (every property required, no `additionalProperties`, nullable rather than optional), so the Phase 2 Azure OpenAI comparison exercises the same schema; that is the test of whether the LangChain abstraction actually holds.
- **Q26 Removals in the schema**: `removals: list[{rule, block_id, quote}]`; **`rule` is a closed enum of the eight text rules**, never a free string. `RM_PHOTO` is never an LLM label: the parser removes every image deterministically. ADR line: if code can do it deterministically, the LLM doesn't get a vote.
- **Q27 Date parser**: accepted `Jan 2020`, `January 2020`, `01/2020`, `1/2020`, `2020-01`, `Jan '20`, `2020`, `Present|Current|to date|now` (case-folded); the LLM references the whole range block once as `dates`; code splits. **Format-parse before range-split** so `2020-01 - 2021-06` survives (the splitter tries the whole string as a single date first, then splits on ` - `, ` – `, ` — `, ` to `). **Runs on canonicalised text** (Q4), so `Jan ’20` and `Jan '20` parse alike. Literal → sorted by first four-digit year, else undated (last, source order). `date_map` maps normalised string → source slice.
- **Q28 Transform log**: one `Run` record (run_id, `LabellerConfig`, prompt/schema label + hash, tokens, cost, per-block ledger, removals, `NORM_INVISIBLE`, `date_map`, `split_map`, residue, unplaced, `label_failed`). Stdout as **a summary line plus per-block detail lines sharing the run id**, because Log Analytics truncates a single field around 32 KB and a 40-block ledger can exceed it; the eval runner takes the in-process object. No `/runs/{id}` endpoint: ADR says it is the first half of a review queue (§3, ADR-0004).
- **Q29 Eval runner**: `python -m cvr.eval.run [--layout] [--candidate] [--no-cache]`, async concurrency ~4 **with retry-and-backoff on 429 from the start**, writes `eval/report.json` (gitignored) and `eval/report.md`, non-zero exit on breach. Report: per-metric totals, per layout, per tag, per candidate, then config/versions/tokens/cost/wall time. `eval/thresholds.yaml`: `placement_accuracy.min`, `appendix_rate.max`, `punctuation_fidelity.hard`. Baseline committed as `eval/baseline-YYYY-MM-DD.json`. CI uploads the report as an artifact (Q23) so a red PR has something to inspect.
- **Q30 Thresholds**: three baseline runs; the baseline file records all three **and the spread**; `placement_accuracy.min` = worst of three minus **one to two points of headroom**, rounded down; `appendix_rate.max` = worst of three plus headroom, rounded up; `punctuation_fidelity` promoted iff all three clean. A wide spread is itself a finding: the prompt is unstable.
- **Q31 Demo PR**: `demo/degraded-prompt` deletes the verbatim-quote rule; draft PR, label `demo`, never merged; branch protection on `main` requires `check` and `eval`. **The degradation is verified to fail three runs out of three** before the demo relies on it, using the same procedure as the thresholds.
- **Q32 Docker / Container Apps**: multi-stage `python:3.12-slim`, `uv sync --locked --no-dev`, non-root; `.dockerignore` drops `.git`, `src/cvr/golden`, `src/cvr/eval`, `fixtures/`, `tests/`, `.env`, `.cache/`. **`ANTHROPIC_API_KEY` is only ever a runtime env var, never a build arg**, and the image is checked for baked-in secrets before the package goes public. Container Apps: external ingress 8000, min 0 / max 1, liveness + readiness on `/health`, key as a Container Apps secret, Log Analytics default. Cold start on scale-to-zero: **warm the endpoint before presenting** (a note in the demo runbook, not a config change).
- **Q33 ADRs**: 0008 claim ledger / residue / separators / backstop narrowness; 0009 LangChain structured output, mandatory quote, RM_PHOTO out of the LLM's hands, cost; 0010 deployment. Each lands in the ticket that implements it; the README-as-ADR links all ten.
- **Q34 Glossary**: written into `CONTEXT.md`: Reference (folded into Assignment), Labelling failure, Composite line, Run, Transform log, Adapter. Residue and Unplaced text were written in Round 2 as an explicit pair (unplaced text is defined in terms of residue).
