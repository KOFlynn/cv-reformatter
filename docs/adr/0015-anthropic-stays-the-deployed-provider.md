# Anthropic Sonnet 5.5 stays the deployed provider; Azure OpenAI is a proven second provider that gpt-5.4-mini does not carry through the gate

**Status: accepted, 2026-10-29; confirmed by the maintainer, 2026-10-30.**

ADR-0014 built the Azure OpenAI path and proved it live; this ADR records the comparison the brief (§10) asks for, run by the method of ADR-0011: three live, uncached eval runs of each configuration over all 48 documents, the same prompt, schemas and thresholds, retry included. The numbers are in `eval/provider-comparison-2026-10-29.json` (assembled by `python -m cvr.eval.compare`, which refuses runs whose versions, documents, thresholds or configuration differ).

**Decision.** The deployed and gated provider stays Anthropic, `claude-sonnet-5-5` at effort `medium` (ADR-0011). Azure OpenAI stays a supported second provider, switchable by configuration alone (ADR-0014), but the model it was compared with, gpt-5.4-mini at `medium`, does not pass the gate. Ticket 21 (the gate and the deployment on Azure) was conditional on Azure winning and is closed as not needed.

| Configuration | Gate | Tunable placement (precision / recall, %) | Structural | Wrongful removals | Appendix | Retries fired (chars placed) | Cost per run | Wall time |
|---|---|---|---|---|---|---|---|---|
| Sonnet 5.5 `medium` (reference) | PASS x3 | 99.65 / 99.73 (every run) | 100 / 100 | 0 | 0.67% | 9 (25) | $1.711-1.712 | 137.5-139.6 s |
| gpt-5.4-mini `medium`, Azure Data Zone Standard | FAIL x3 | 43.89-44.42 / 43.97-44.50 | 100, 99.63, 100 | 7, 6, 9 | 0.57-0.64% | 14, 16, 13 (369, 480, 278) | $1.029-1.050 | 418.7-435.7 s |

Tokens per run: Sonnet about 328,400 in and 105,400 out; gpt-5.4-mini 209,500-221,000 in and 171,100-177,000 out. Three runs cost $5.13 for Sonnet and $3.13 for gpt-5.4-mini. Azure ran at `--concurrency 2` (the 200K TPM deployment), Sonnet at 4, which accounts for part of the wall time.

**Why gpt-5.4-mini does not pass.** It failed the hard `removal_precision` gate in every run: c04's `RM_REFEREE` removed the end of a content line ("reference available") and c07's `RM_PERSONAL` removed "EU citizen" in every run, and c10's `RM_PERSONAL` removed "India" in run 3. Haiku 5.5 failed in the same two places in Phase 1.5. It failed the structural gate in run 2 (c08, text-box, 99.63%) and the tunable placement threshold in all three runs, far below the 98% minimum, with single-column the only Layout that passes (98.59-99.65%) and header-footer and two-column near 14% and text-box near 48%. Everything the brief calls a hard gate on content (added, dropped, provenance, PII, images, ordering, punctuation) was zero, so the failures are of labelling quality, not of what reaches the document. Its retries fired more often than Sonnet's and placed more characters, but a retry only adds unplaced text (ADR-0012) and cannot correct a leaf placed in the wrong field. The cause of the placement collapse was not diagnosed here: the report holds counts, not a per-leaf diff, and a diagnosis (or a prompt tuned for this model) is a separate piece of work.

**The limitation, plainly.** This is a comparison of Sonnet 5.5 with one small Azure model, not with Azure OpenAI as such. The plan was gpt-5.4 (ticket 20 was written for it). `cvr_sub` had no Data Zone Standard quota for gpt-5.4 in any EU region (checked 2026-10-24), and only gpt-5.4-mini had quota (200K TPM, in swedencentral among others). A quota request for gpt-5.6-terra in swedencentral was refused on 2026-10-29: Sweden Central has no capacity to expand, and Microsoft's advice was to resubmit with other regions or wait 30 days or more. The stronger models are accepted by the provisioning wizard and priced in `PRICE_TABLE`, but no number here speaks for them, and "Azure OpenAI fails the gate" would be a wrong reading of this record. The finding is that the cheaper model is not enough, as Haiku was not in Phase 1.5.

**What reopens the decision.** Any of: quota for gpt-5.4 or gpt-5.6-terra on an EU Data Zone deployment (add the deployment with the wizard and run the three-run comparison again, labelled and dated); a change to the prompt, the retry prompt, either schema or either model, in which case the comparison is re-run (as ADR-0011 already requires for a model change); a requirement for EU-only processing that outweighs the gate. If Azure then wins, ticket 21 describes the work: a separate, narrow Entra identity for the `eval` job, ADR-0014's section on it, and switching the deployment's configuration.

**Anthropic has no EU-only processing guarantee** (ADR-0013 and ADR-0014 say so): the labeller sends the document's text to Anthropic's API, where Azure's Data Zone deployment would keep processing in the EU. That is a real advantage of the Azure path that this verdict does not weigh against the gate: the data are synthetic, there are no real CVs in this project, and the thresholds are the product's bar. For real candidate data it would be the first thing to revisit.

**The thresholds are unchanged**, as in ADR-0011: they are the bar, not a description of Sonnet. Loosening them until gpt-5.4-mini passed would be fitting the test to the model.

**Considered options:** Azure as the deployed provider (rejected: fails the gate on every run; also moot until a stronger model has quota). Lowering the Azure effort or raising it to `high` (not pursued: the ticket's rule was `medium` on both sides, and a second labelled comparison is the place for it). A model-specific prompt for gpt-5.4-mini (not pursued: the prompt is shared, as ADR-0011 decided for Haiku). Running the comparison with the Phase 1.5 Sonnet runs (rejected: they predate the retry and carry no retry versions).

**Consequence:** nothing in the code, the deployment or the gate changes. `eval/thresholds.yaml` is untouched, the app stays on Sonnet 5.5, the Azure provider stays in the code and is proven by ADR-0014's live run. The record `eval/provider-comparison-2026-10-29.json` is the evidence; the Azure runs cost about $3.13 and the Sonnet runs $5.13.
