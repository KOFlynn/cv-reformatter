# Provenance is checked per rendered unit; token multisets, PII and image checks cover its blind spots

The brief describes the added-text and dropped-text gates as multiset comparisons of tokens. A multiset is order-blind: swap two words inside a bullet, or move a word between bullets, and both gates still pass, so a bag of words does not prove the invariant. The primary check is therefore `provenance_violations`: every rendered unit (a bullet, a title, a skill, a date) must be an exact canonicalised substring of some source block, unless it is template text or a normalised date mapped back to its source. The multiset checks remain as the coarse backstop.

Provenance has its own blind spots, and each is closed by a separate hard gate rather than by stretching the definition:

- **A leaked email is correctly copied source text**, so neither `added_tokens` nor `provenance_violations` can see it. `pii_leak` is a separate gate that matches fixture PII values, with variants (digits-only phones, casefolded emails, whitespace-collapsed addresses), reporting each hit once under the most specific removal rule.
- **A photo is not text**, so no token metric can see it. `image_leak` compares the output document's embedded images (by count and content hash) against the template's own image set.
- **Template text is whitelisted by word**, so "Experience" is permitted wherever it appears. Provenance, which checks whole units against whole blocks, is what stops template words being used as filler.

All metrics share one `canonicalise()` and one `tokenise()`, held in `cvr/text.py` at the bottom of the dependency stack so eval, the golden-set generators and the pipeline all reach the same table without depending on each other. `canonicalise()` is NFC first, then an explicit confusable table (curly quotes, dashes, ellipsis, exotic spaces, invisible characters), then whitespace collapse. NFKC would do much of the table for free but also rewrites things that must stay (`½` → `1⁄2`, `™` → `TM`), so NFC plus an explicit table is deliberate. `tokenise()` canonicalises, splits on whitespace, strips punctuation from token edges only, and drops empties: `Engineer,` in the source matches `Engineer` in the output while `C++`, `O'Flynn` and `2019-2022` survive intact and typos stay protected. No metric normalises on its own.

Canonicalising both sides creates one more blind spot: if the renderer silently straightens a curly apostrophe, no canonicalised metric notices, and the "punctuation is never changed" rule would be claimed but unchecked. `punctuation_fidelity` compares the raw located source span with the raw rendered unit, byte for byte, after provenance has found the span. It starts as a reported metric and is promoted to a hard gate once the baseline shows it is clean. The one deliberate modification the pipeline may make, stripping invisible characters, is a named rule (`NORM_INVISIBLE`) written to the transform log, because no token metric can ever see it.

**Consequence:** the "test the test" suite corrupts a fake pipeline one way at a time, and asserts each corruption fails exactly its declared blast radius. The rows "swap two words" (fails provenance, passes multisets), "re-emit the email" (fails PII, passes everything else) and "straighten an apostrophe" (fails punctuation fidelity, passes provenance) are the documented proof that no single check would have been enough.
