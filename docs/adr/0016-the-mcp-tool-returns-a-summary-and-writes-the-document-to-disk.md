# The MCP tool returns a summary and writes the document to disk

Phase 3 adds an MCP server, `cvr.mcp`, that exposes one tool, `reformat_cv`, to Claude Desktop. It runs locally over stdio and calls the same `reformat` in-process. The tool's result goes into the calling model's context, which is a new channel for candidate text alongside the provider, the logs and the trace that ADR-0013 bounds. We decided the result carries **no candidate text**. It names where the output document was written and gives the run id, whether the labelling failed, the number of retries, removal counts by rule, the unplaced count, tokens and cost. The document itself goes to disk.

Claude Desktop does not give a local server the files attached in the chat, so the user names a path. That path must resolve inside one configured **workspace** (`CVR_MCP_ROOT`; symlinks and `..` are resolved first), end in `.docx` and be at most `MAX_UPLOAD_BYTES`. The output is written next to the input as `<stem>-reformatted-<first 8 characters of the run id>.docx`, so it never overwrites anything and its name leads to its trace and log lines. A file name can itself be PII (`Jane Doe CV.docx`), so the path appears in the tool result only, which tells the model nothing the user did not type. It never appears in the logs or the trace, as with the API's upload name. An error is a tool error with a fixed message in the API's categories, never the exception's text.

**Considered options.** Returning the output's text so Claude can discuss it was rejected: the text, even with PII stripped, would go to a second LLM, and the model could restate or reword the candidate's words in the chat. That would blur the invariant that no LLM writes output text (ADR-0001). Returning the `.docx` as an embedded resource was rejected because Claude Desktop does not save a tool's resource to disk, so the user could not open it. A remote server on `cvr-ca` was rejected for this phase because it would need ingress kept open, a way to authenticate and a way to get the file's bytes to it. Writing the protocol by hand was rejected in favour of the official SDK, because the evidence is in the tool's boundary, not in how messages are framed.

**Consequence.** Claude can report what happened to a CV but cannot quote it. The canary leak test gains an MCP case: canaries in the body and in the file name, none in the tool result's text fields, the logs or the trace.
